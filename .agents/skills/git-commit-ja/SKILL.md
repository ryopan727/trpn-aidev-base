# 日本語でGitコミットを書く

## メッセージの方針

- 件名と本文の説明は日本語で書く。既存の履歴が英語でも、それに合わせて英語に戻さない。
- 件名は変更内容が分かる短い1文にする。「修正」「更新」だけで済ませず、何をどう変えたかを書く。
- API・FastAPI・Docker Composeなどの技術名、コードの識別子、ファイル名は原表記を使う。
- リポジトリがConventional Commitsなどの形式を指定している場合は、その形式を守る。`feat:`・`fix:`・`docs:`などの接頭辞やscopeは維持し、説明部分を日本語にする。指定がなければ接頭辞は必須にしない。
- 本文は、件名だけでは伝わらない理由・影響・検証結果がある場合に日本語で添える。実施していない検証を成功と書かない。

## コミット時の進め方

1. ユーザーの指示と適用される `AGENTS.md` を確認し、作業対象のブランチ・worktreeで `git status` と差分を読む。
2. 今回の作業に必要な変更だけをステージする。既存のステージ済み変更も確認し、別作業の変更を勝手に含めたり外したりしない。
3. `git diff --cached` の実際の内容に基づいて日本語のメッセージを作り、既に許可された範囲でコミットする。コミットまで含む作業指示があれば、改めて承認を求めない。
4. 作成後に `git log -1 --format=%B` で件名・本文を確認する。

メッセージ案だけの依頼ではコミットしない。スキルの利用だけを根拠にpush・PR作成・過去のコミットの書き換えへ作業を広げない。既にそれらが依頼範囲に含まれている場合は、その指示に従う。

複数行の本文を付ける場合は、メッセージを一時ファイルに書き、`git commit --file <メッセージファイル>` で渡す。コード名やバッククォートを含む文章がシェルのコマンド置換として実行されないようにする。

## 件名の例

- `タスクの登録・一覧・完了APIを追加する`
- `E2EをCompose上のAPIへの実HTTP通信に変更する`
- 形式の指定がある場合：`fix: 入力不備の応答を400に統一する`
