# テスト設計：タスク管理

文書の状態：決定済み

> 2026-11-22：タグ名の直接指定による付与・解除・一覧取得と、その制約・API・データモデルをユーザー承認済み（TASK-Q-004）。

## 1. テスト範囲・役割分担

[共通方針](../../../steering/api/testing.md)を適用する。実行は[operations.md](operations.md)のTaskを使う。

| 段階 | 範囲・目的 |
| --- | --- |
| 単体 | domainのタイトル・状態ルール、applicationの保存確定／取り消し、DBを差し替えたpresentationの入力検証・エラー応答。 |
| 結合 | 実PostgreSQLに対するRepository・Unit of Work・Flyway。保存結果、順序、ページ分割、rollback、並行完了を確認。 |
| E2E | testコンテナのHTTPXからCompose上のapi-testへ実HTTP通信し、Uvicorn・FastAPI・bootstrap・4層・db-testを通してHTTP応答まで確認する。登録→取得→一覧→完了→再取得に加え、別接続からDBの保存結果も確認する。画面は対象外。 |
| 起動・永続化確認 | 通常の停止・再起動後の保存結果は、TASK-AC-009として別途確認する。E2EのAPI起動確認に加えて、永続ボリュームの保持を検証する。 |

## 2. 重要な検証観点

以下のIDは[要求仕様](../requirements.md)の受入条件に対応する。テスト名・コメントから対応IDを参照できるようにする。

| 受入条件 | 主な検証段階・期待 |
| --- | --- |
| TASK-AC-001 | E2Eで登録結果と取得結果、201・Locationを確認。単体でタイトルの境界と保持を確認。 |
| TASK-AC-002 | HTTP境界で400・公開エラー形式を確認。E2Eでは代表例の保存なしを確認。 |
| TASK-AC-003・004 | 結合で同時刻を含む順序・件数・空ページ。HTTP境界でpage・page_sizeの境界、型、未知クエリ。 |
| TASK-AC-005 | 単体で遷移・再完了、結合で同時完了、E2Eで他項目を変えないこと。 |
| TASK-AC-006・007 | HTTP境界とE2Eで空更新・null・不正状態、UUID不正400と不存在404を区別。 |
| TASK-AC-008 | 単体でcommit失敗を成功扱いにしないこと、結合で未確定変更のrollback。 |
| TASK-AC-009 | 開発用の使い捨てデータを登録・完了後、`task dev:down`→`task dev:up`で保存結果を再取得。 |
| TASK-AC-010 | ログ捕捉とエラー応答の検査。秘密値やタイトルが出ず、内部例外の詳細を返さない。 |

横断的に `X-Request-ID`、UTCの日時、未知入力の拒否、更新項目の省略とnullの区別を確認する。手書きOpenAPIと生成スキーマを照合し、自動生成の422が残っていないことも確認する。メッセージ文言の完全一致など、契約でない表現の固定は避ける。

## 3. テストデータ・依存先の扱い

DBを使うテストに `db` マーカーを付ける。結合は `tests/tasks/infrastructure/`、E2Eは `tests/e2e/` をTaskで選択する。DB不要テストではRepository等を差し替える。DBありテストは開発DBと分離し、Flyway履歴を保って各テストのデータを片付ける。SQLiteへの置換や実データ・秘密値の使用はしない。

順序の検証では作成時点・IDが制御されたデータを用意する。単体のHTTP境界テストではTestClientのlifespanを実行し、500応答の確認では例外再送出を無効にする。E2Eは `httpx.Client` を使い、接続先を `http://api-test:8000` に固定する。アプリの直接呼び出し・ASGITransport・依存の差し替えは行わず、接続不能やタイムアウトは失敗とする。DB用fixtureはテストデータの初期化・後片付けと保存結果の確認だけを担当する。永続化の受入確認には専用のローカルComposeプロジェクトを用い、通常の開発データを変更しない。

### タグ追加の検証（承認済み）

| 受入条件 | 検証段階と対象 |
| --- | --- |
| AC-011・012 | 単体：名前の境界・禁止文字・厳密一致、HTTPの201/200/400。結合：主キーによる重複防止、同時付与と別タスクの独立性。 |
| AC-013・015 | 単体・E2E：付与→一覧→解除→一覧→再解除404、タスクなしとタグなしの区別、UUID不正400、本文・未知クエリ拒否。ルーティング不一致は404として検証する。 |
| AC-014 | 結合：異なる名前の固定順序、ページ・全件数・空一覧、読み取りスナップショットの一致。単体：ページ境界。 |
| AC-016 | 単体：保存失敗を成功にしない。結合：rollback、外部キー、同時付与・解除の確定順に対応する結果。起動確認：専用Composeの再起動後も保持。 |
| AC-017 | 単体・E2E：有効・無効のタグ名、エンコード済みパス、不一致ルート、内部障害のログと応答に入力値・SQL・秘密値が漏れない。 |
| AC-018 | 既存unit・integration・E2Eの回帰。移行確認：専用Composeの既存V1適用済みDBへ追加マイグレーションを適用してタスクを維持し、タグは0件。 |

IDにはTASK-を補う。E2Eは既存どおりCompose上のAPIへ実HTTP通信し、別DB接続で付与・解除の保存結果を確認する。DBテストの後片付けは子のtask_tagsから親のtasksの順とする。既存のTaskで実行できる配置を使う。
