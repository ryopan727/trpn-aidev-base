# セキュリティ設計：タスク管理

文書の状態：決定済み

## 1. 適用する共通方針・対象範囲

[入力検証](../../../steering/api/input-output-validation.md)、[パラメーター化SQL](../../../steering/api/data-storage.md)、[秘密情報](../../../steering/api/settings-and-secrets.md)、[エラー処理](../../../steering/api/error-handling.md)、[ログ](../../../steering/api/logging.md)の方針を適用する。認証・認可は合意済みの対象外であり、全利用者が同じタスクを扱う。

## 2. 保護対象と取り扱い

| 対象 | 扱い |
| --- | --- |
| タイトル | 自由入力の業務データ。ログへ出さず、テストでは架空の値を使う。 |
| DB接続情報 | 共通設定で管理する。Git・イメージ・ログ・応答に秘密値を含めない。 |
| 内部障害情報 | クライアントには共通の公開エラーだけを返す。SQL・接続情報・例外の内部情報を露出しない。 |

## 3. 領域固有の対策・制約

ローカル開発での試用を対象とし、APIを外部へ公開する運用は含めない。タイトルはSQLパラメーターとして扱い、ID・作成日時などの任意指定は拒否する。利用者ごとのデータ隔離が必要になった場合は、認証・認可と要求範囲を改めて決定する。
