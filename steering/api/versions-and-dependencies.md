# バージョン・依存管理

状態：決定済み（2026-11-08）

依存管理に **uv** を採用し、バージョンは選定時点の最新安定版を使用します。
プレビュー版は対象にせず、採用した具体的な版を固定します。更新時に改めて最新安定版を確認し、動作検証後に固定情報を更新します。

## 採用バージョン

2026-11-08の選定で決定した、初回実装の固定バージョンです。以下の表は採用版を示し、閲覧時点の最新版を自動的に追従するものではありません。

| 対象 | バージョン | 確認元 |
| --- | --- | --- |
| Python | 3.15.2 | [Python公式](https://www.python.org/downloads/) |
| FastAPI | 0.162.1 | [PyPI](https://pypi.org/project/fastapi/0.162.1/) |
| uv | 0.13.7 | [PyPI](https://pypi.org/project/uv/0.13.7/) |

Pythonは `.python-version` とDockerのPythonイメージで3.15.2に揃え、プロジェクトの許容範囲は `>=3.15,<3.16` とします。
FastAPIの直接依存は `fastapi==0.162.1` とし、間接依存も `uv.lock` で固定します。uv自体も0.13.7に揃えます。

現時点ではバージョンの公開状況を確認した段階です。Python 3.15での全依存のインストール・組み合わせの動作検証は初回実装時に行います。互換性の問題が出た場合は、原因と選択肢を確認して方針を見直します。

全体レビュー時にはPyPIに[FastAPI 0.162.2](https://pypi.org/project/fastapi/0.162.2/)の公開も確認しました。既に選定した0.162.1はこのレビューで自動更新せず、新版への変更は互換性検証を伴う更新として扱います。

## 依存管理の単位とファイル

管理単位は `apps/backend/` 全体で1つとし、サブドメインごとには分けません。

| ファイル | 役割 |
| --- | --- |
| `apps/backend/pyproject.toml` | Pythonの許容範囲、直接使うパッケージ、開発用パッケージを宣言する。 |
| `apps/backend/uv.lock` | 間接依存を含め、解決したバージョンを記録する。uvで生成する。 |
| `apps/backend/.python-version` | 開発で使用するPythonの具体的なバージョンを指定する。 |

この3ファイルはGitで管理します。`uv.lock` は手で書き換えません。
Python本体、Dockerイメージ、uv自体は `uv.lock` では固定されないため、それぞれの設定で版を揃えます。[uvのファイル構成](https://docs.astral.sh/uv/concepts/projects/layout/)を参照してください。

## 実行用・開発用の分離

- 実行用パッケージは `pyproject.toml` の `[project]` の `dependencies` に記載します。
- テスト・整形などの開発用パッケージは `[dependency-groups]` の `dev` に記載します。
- アプリから直接使うパッケージは直接依存に記載します。例えばPydanticを直接importするなら、FastAPIの間接依存であっても宣言します。
- `requirements.txt` を別の正本として二重管理しません。連携先が必要とする場合だけ、ロック情報から出力します。

## 環境の再現と更新

- 通常の環境構築・CIは `uv sync --locked` を使い、宣言とロックが一致しない場合はエラーにします。
- 実行用だけを導入する場合は `uv sync --locked --no-dev` を使います。
- パッケージの追加・更新はuvで行い、宣言とロックの差分を確認してテストします。版を完全指定した依存の更新では、宣言も変更します。
- 通常の起動やビルドのたびに最新版へ更新しません。更新作業で最新安定版を選び直し、動作確認とともに記録を更新します。

同期と更新の挙動は[uv公式](https://docs.astral.sh/uv/concepts/projects/sync/)を参照してください。
コマンドは初期設定後に `apps/backend/` で実行する想定です。Docker内でも同じ宣言・ロックを使い、組み込み方は[No.12](docker-compose.md)に従います。

今回は方針のみの決定で、管理ファイルの生成やインストールはまだ行っていません。起動サーバーは[No.12](docker-compose.md)、テストツールは[No.13](testing.md)、整形ツールは[No.4](coding-conventions.md)、DB関連ツールは[No.9](data-storage.md)で決定済みです。
