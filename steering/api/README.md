# APIの技術方針：策定項目

Python・FastAPI・Docker Composeを使ったREST API開発について、決定した技術方針をまとめます。
No.10の認証・認可は今回は対象外とし、それ以外の項目は決定済みです。各文書に残した比較表の代替案は、採用事項とは区別してください。

## 決定済みの前提

- 言語：Python
- Webフレームワーク：FastAPI
- API方式：REST API
- 開発環境：Docker Compose
- 依存管理：uv。Python・FastAPI・uvは選定時点の最新安定版を採用し、具体的な版を固定する。
- コード整形・lint：Ruff。型チェック：mypy。
- 処理方式：通常の `def` による同期処理を基本とする。
- データ保存：PostgreSQL。Psycopg 3でSQLを明示して同期実行し、同期接続プールを使う。DB構造の変更管理にはFlywayを採用する。
- 認証・認可：今回は実装対象外とする。
- 設定値の管理：`.env` に記載し、Composeからコンテナの環境変数へ渡す。Pythonでは標準ライブラリの `os.getenv()` で取得する。
- 実装の配置先：`apps/backend/`
- アーキテクチャ：サブドメインごとのDDD4層構成。依存性逆転によってドメイン層を技術の実装から独立させる。
- 共通処理の配置先：`apps/backend/app/shared/`

## 一つずつ決めるときの進め方

1. 対象項目の目的と選択肢を確認する。
2. 初学者にとっての分かりやすさ、実装・運用の負担を比較する。
3. 採用する方針と理由を決め、この文書に追記する。

詳細が増えた項目は、その時点で個別ファイルに分けます。
No.1〜9・11〜14は決定済み、No.10の認証・認可は今回は対象外です。今回策定した技術方針に未決定の項目はありません。

## 実装・個別仕様・配備時に扱う事項

各パッケージ・イメージの未固定の版と互換性確認、Composeの具体的な設定値は初回実装時に詰めます。最新安定版を確認して固定する方針は決定済みです。
実際のサブドメイン・業務ルールは各アプリの仕様、本番の起動構成・秘密情報の供給方法は配備先が決まった時点で扱います。No.4で見送った詳細なコーディング規約やNo.10の認証・認可は、未決定事項として追加しません。
