# trpn-aidev-base

GPTを使い始めた初学者が、AIと相談しながら開発を進めるためのAI駆動開発キットです。
Python・FastAPIでREST APIを作り、Docker Composeで開発環境を起動する方針です。

## 開発の始め方

1. このリポジトリを自分のGitHubアカウントにフォークし、ローカルへcloneします。
2. ファイルを読み書きできるAI開発ツールでリポジトリを開き、[AGENTS.md](AGENTS.md)を読むよう指示します。
3. 作りたい機能を1つ選び、下の「要求・設計モード」で相談します。サブドメインは「注文」など業務のまとまりで、分け方が未定ならAIと相談できます。
4. AIが作成した要求・設計を確認して承認し、「自律実装モード」で実装を依頼します。
5. 作成されたPR（変更内容をレビューするための提案）で、コード・仕様との対応・テスト結果を確認します。

現在のキットには方針と設計テンプレートがあり、アプリ・Compose・Taskfileはまだ実装されていません。初回実装で必要なものを整えます。実装時にはGit・Docker Compose・Taskを実行できる環境と、作業先リポジトリへのpush・PR作成に必要なGitHubの認証・権限を用意してください。

## 2つのモードの使い方

### 要求・設計モード

作りたいことを伝え、要求仕様・基本設計・API仕様・必要な詳細設計をまとめます。AIは具体的な成果物を提示して承認を求めます。以下の「注文登録」は例なので、自分の機能に置き換えてください。

```text
モード: 要求・設計
対象: 注文登録機能

AGENTS.mdと関連するsteering・specsを読んで進めてください。
商品と数量を指定して注文を登録できるREST APIを作りたいです。
不明点を確認しながら、小さな範囲で要求仕様と設計をまとめてください。
specsのテンプレートを使い、整合確認後に承認する内容を提示してください。
```

「期待する動作」「今回の対象外」「失敗時の扱い」を確認し、修正があれば伝えます。問題なければ「提示された要求・設計を承認し、決定済みにしてください」と指示します。承認は設計への合意であり、実装完了を意味しません。

### 自律実装モード

承認済みの要求・設計を指定すると、AIが実装・テスト・修正・レビュー・コミット・push・PR作成まで進めます。次のパスは、設計時に作成した実際のサブドメイン名へ置き換えてください。
作業ごとに専用ブランチとGit worktree（同じリポジトリの別の作業フォルダ）を使います。同じ作業では既存のworktreeを引き継ぎます。

```text
モード: 自律実装
対象: specs/orders/の承認済みの注文登録機能

AGENTS.mdと関連するsteering・specsに従って実装してください。
この作業専用のブランチとGit worktreeを用意し、その中で作業してください。
初回実装に必要なCompose・Taskfileも対象範囲で整備してください。
必要なテスト・静的解析・OpenAPIの照合を行い、失敗を修正してください。
差分を確認してコミット・push・PR作成まで進め、検証結果を報告してください。
```

要求・API契約・対象範囲を変える必要がある場合は、AIから確認を求めます。マージ・デプロイは別の指示で扱います。起動・テストの具体的なTaskコマンドは、実装後の各領域の `detailed-design/operations.md` を参照してください。
モードはチャットで指定でき、途中で切り替えられます。詳しい範囲と完了条件は[開発モード](steering/aidd/modes.md)を参照してください。

## フォルダ構成

```text
.
├── README.md
├── AGENTS.md          # AIへの指示と開発モードの指定方法
├── steering/          # プロジェクト全体の方針・取り決め
│   ├── aidd/          # AI駆動開発の進め方
│   ├── api/           # APIの技術スタック・設計方針
│   └── templates/     # 取り決めを記載するためのテンプレート
├── specs/             # サブドメインごとの要求仕様・設計
│   └── templates/     # 仕様を記載するためのテンプレート
└── apps/              # アプリケーションの実装
    └── backend/       # Python・FastAPIによるREST API
```

`steering` に共通のルール、`specs` にサブドメインごとの仕様・設計、`apps` にコードを置きます。
AIへの作業指示と2つの開発モードの指定方法は [AGENTS.md](AGENTS.md) にまとめています。
まずはこの構成を土台に、必要な取り決めを一つずつ追加します。
[AI駆動開発の進め方](steering/aidd/README.md)、[APIの技術方針](steering/api/README.md)、[仕様・設計の成果物とテンプレート](specs/README.md)を整備しています。具体的なサブドメインの仕様・実装は、必要になった時点で追加します。空フォルダはGitには保存されません。
